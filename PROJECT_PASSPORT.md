# Паспорт проекта: ВРуки (v-ruki.ru) v1.0

Этот документ описывает внутреннее устройство приложения, структуру файлов и логику взаимодействия компонентов.

---

## 1. Архитектурная схема
**Стек:** Vite + React (Frontend) <-> Supabase (Backend/Database/Auth)

### Поток данных:
1. **Auth:** Supabase Auth -> `AuthContext` -> Локальное состояние пользователя + Профиль из БД.
2. **Объявления:** Форма -> `clientValidation` -> `supabase.js` -> БД (RLS + SQL Constraints).
3. **Модерация:** Админ -> `AdminDashboard` -> Запрос записей со статусом `moderation` -> Смена статуса в БД.

---

## 2. Структура файлов и их назначение

### Корень проекта
*   `index.html` — Точка входа в приложение, содержит SEO-теги.
*   `README.md` — Инструкция по развертыванию и SQL-дамп.
*   `PROJECT_PASSPORT.md` — Данный технический документ.
*   `public/_redirects` — Конфигурация для Render.com (SPA routing).

### Исходный код (`src/`)
#### Ядро и Конфигурация
*   `main.tsx` — Инициализация React и монтирование в DOM.
*   `App.tsx` — Главный роутер приложения. Определяет все маршруты (`/`, `/admin`, `/login` и т.д.).
*   `lib/supabase.ts` — Инициализация клиента Supabase. Использует переменные окружения `VITE_`.
*   `context/AuthContext.tsx` — **Сердце приложения.** Управляет сессией, загружает профиль пользователя (`role`, `is_blocked`) и раздает эти данные всем компонентам.

#### Типы и Данные
*   `types/database.ts` — TypeScript интерфейсы. Описывают структуру таблиц `Listing`, `Profile`, `Category` для исключения ошибок типизации.
*   `constants/data.ts` — Статические данные. Список городов РФ и категорий. Используется как fallback, если БД пуста.

#### Утилиты (Бизнес-логика)
*   `utils/clientValidation.ts` — Проверки перед отправкой в БД (длина текста, размер фото). **UX-слой.**
*   `utils/logger.ts` — Логирование ошибок и подозрительных действий в таблицу `security_logs`.

#### Компоненты (`components/`)
*   `Header.tsx` — Шапка. Логика отображения кнопок (Админка видна только для `role: admin`).
*   `Footer.tsx` — Подвал с навигацией.
*   `ListingCard.tsx` — Карточка объявления. Используется на главной и в категориях.

#### Страницы (`pages/`)
*   `Home.tsx` — Главная страница. Логика поиска и вывода последних объявлений.
*   `Login.tsx / Register.tsx` — Формы авторизации.
*   `CreateListing.tsx` — Сложная форма подачи. Взаимодействует с `Storage` (загрузка фото) и `Database` (создание записи).
*   `ListingDetails.tsx` — Просмотр одного объявления. Динамически подгружает автора и изображения.
*   `MyListings.tsx` — Личный кабинет. Управление своими записями.
*   `AdminDashboard.tsx` — **Панель модератора.** Доступна только для ролей `admin/moderator`.
*   `CategoryPage.tsx` — Фильтрация объявлений по категориям.

## 4. Логика основных процессов

### Процесс публикации:
1. Пользователь заполняет форму.
2. `clientValidation` проверяет: Заголовок > 10 симв, Описание > 30 симв, Фото < 5МБ.
3. Если ОК -> Загрузка фото в Supabase Storage -> Получение URL.
4. Запись в таблицу `listings` со статусом `moderation`.
5. **На уровне БД:** Срабатывает RLS (проверка: не более 3-х за 24 часа). Если лимит превышен — БД вернет ошибку, фронтенд её отобразит.

### Процесс модерации:
1. Админ открывает `/admin`.
2. Запрос в БД: `select * from listings where status = 'moderation'`.
3. Админ жмет "Одобрить" -> `update listings set status = 'active'`.
4. Объявление мгновенно становится видимым для всех на `Home.tsx`.

## 5. Безопасность (Иерархия)

1.  **Уровень фронтенда (Vite):** Скрытие UI-элементов, UX-валидация полей.
2.  **Уровень БД (Supabase) - ГЛАВНЫЙ:**
    *   **RLS Policies (listings):** 
        *   `SELECT`: Публика видит только `active`. Админы и авторы — всё.
        *   `INSERT`: Лимит 3 в день, проверка на бан пользователя.
        *   `UPDATE`: Статус может менять только админ. Обычный пользователь может менять только свои черновики.
    *   **RLS Policies (security_logs):** Только админ может просматривать логи.
    *   **SQL Constraints:** Проверка длины текста и неотрицательной цены на уровне ядра PostgreSQL.
3.  **Уровень Storage (Фото):**
    *   Загрузка разрешена только авторизованным пользователям.
    *   Публичное чтение всех изображений.
    *   Удаление разрешено только владельцу файла.
